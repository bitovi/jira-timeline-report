Data storage — a new Global Settings panel

Mockup for spec/020-report-and-team-data/plan.md. Sits alongside Teams / Features / Theme under Global Settings in the existing sidebar (ReportSettings.tsx), reached with changeSettings('STORAGE'). Four states, left to right: today, near the limit, after choosing a Jira project, and the failure case.

The capacity meter is Phase 1 and ships on its own — it's useful even if nothing below it is ever built. Everything else is Phase 5.

Sidebar icons — the five real ones from public/images/, plus the new storage.svg. Same #626F86 fill, same solid-fill (no stroke) construction.

The new icon is a three-band cylinder: a filled cap ellipse plus two crescents, drawn only with <path> fills like every other icon in the set. Nothing in the sidebar renders it yet — it's just the asset. Note the existing set isn't uniform: magnifying-glass, calendar, and team are 18×18 viewBoxes drawn edge-to-edge, while features and theme are 24×24 with padding baked in, and ReportSettings.tsx renders features at its natural 24px while forcing theme to w-[18px]. storage.svg follows the 18×18 edge-to-edge convention, which is the one the majority uses. Everything above is rendered at 18px.

Two things the mockup is deliberately taking a position on. First, the destination is “a Jira project,” not “create a STATREPS project” — pointing at an existing project the customer already has avoids gating the feature behind a site-admin ticket. Second, App storage is described as “Backup,” never “Deprecated.” It's the only mode where saving a report needs no Jira write permission, so it stays supported. See plan.md § Risks.
