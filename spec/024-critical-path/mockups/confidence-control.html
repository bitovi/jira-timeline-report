Confidence control — compact alternatives to the Median…90% slider

The Auto-Scheduler controls row currently gives the uncertainty slider flex-grow, so it eats every pixel left over after Report on, Report type, Start date and Update Epic Dates. There is nowhere to put a Critical path button. These options all shrink the control to a fixed, small footprint.

Hard requirement carried through every option: once the pointer goes down, the user can keep changing the value without releasing. Every widget below is drag-live — press, move, watch the number change, release to finish. Nothing requires a click-then-click-again.

All nine stops are preserved: Median (50), Average (55), then 60 / 65 / 70 / 75 / 80 / 85 / 90.

Option A — Press-and-hold vertical slider recommended

A 96px trigger button, driveable two ways. Press and hold — the popover appears with the current stop already under your cursor, so you are mid-drag the instant it opens; move up/down, release to commit. Or click to open and it stays up — and because the open popover is itself a slider, you can then press anywhere in it and keep dragging without releasing. Neither path ever forces a release mid-adjustment.

Press-and-hold (scrubbing popover)

Zero-release interaction: pointerdown opens it and starts the drag in one gesture.

Value: 80% · trigger width ~96px
  • Smallest always-on footprint of any option that still shows the value.
  • One uninterrupted gesture — satisfies the hard requirement literally.
  • Once open, the list is still a slider — press and drag anywhere inside it.
  • Vertical list has room for the full word labels (“Median”, “Average”).
  • Popover overlays the report while dragging.

Option B — Always-visible vertical rail

No popover, no click-to-reveal. A 22 × 64px vertical track sits inline in the controls row. Press anywhere on it and drag — it snaps to the nine stops. Roughly 110px wide including the value label.

Inline vertical rail

Everything is visible and directly manipulable — no reveal step at all.

Value: 80% · footprint ~110 × 64px
  • Nothing is hidden; discoverable at a glance.
  • Drag starts immediately, never occludes the report.
  • 64px tall — forces the controls row taller than 30px.
  • Too short to label all nine stops; only ends get labels.

Option C — Scrubbable number (Figma-style)

The value itself is the control. Press on 80% and drag horizontally; every ~20px advances one stop. Arrow steppers on the right for keyboard/precision users. ~84px total, the most compact option here.

Drag-to-scrub value

Familiar from design tools; no popover, no extra chrome, infinite drag range.

Value: 80% · footprint ~84 × 30px
  • Tiniest footprint; fits in a 30px-tall row.
  • Drag never ends — you can keep scrubbing past the edge of the widget.
  • Not discoverable — nothing signals “draggable” but the cursor.
  • No sense of where 80% sits in the range.

Scrub + mini rail hint

Same scrub, plus a 3px progress bar underneath so position in the range stays legible.

Value: 80% · footprint ~84 × 34px
  • Recovers the “where am I in the range” signal for 4 extra pixels.
  • Still relies on hover to teach the interaction.

Option D — Drag-across segmented strip

A native <select>-like row of nine cells. Press on any cell and slide across the others — the value follows the pointer, release commits. It is a horizontal slider with the ticks as the track, so it costs ~230px instead of 600.

Recommendation

  • Ship Option A. It is the only design that is both small enough to free ~400px and honours the press-once-and-keep-adjusting requirement without compromise — pointerdown opens the popover already positioned so the current stop is under the cursor, which means the drag has effectively begun before the user notices the popover appeared.
  • Keep Option D as the fallback if overlay-while-dragging tests badly. It is a drop-in fixed-width replacement with no hidden state.
  • Option A should still support click → stays open → click a stop and arrow-key adjustment, so it degrades to a normal dropdown for keyboard and touch users.
  • Whichever wins, the control needs a Confidence label — today the tick labels carry that meaning and they disappear in every compact option.
